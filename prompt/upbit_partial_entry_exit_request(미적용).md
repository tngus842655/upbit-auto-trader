# 업비트 자동매매 분할매수 / 분할매도 기능 구현 요청서

## 1. 목적

현재 자동매매 시스템은 전략에서 `BUY / SELL / HOLD` 신호가 발생하면 해당 시점의 가격으로 매수 또는 매도하는 구조입니다.

이 구조에서는 전략 신호 이후 가격이 더 유리한 방향으로 움직여도 이를 충분히 활용하지 못합니다.

예:
```text
BUY 신호
→ 현재 가격 100에서 매수
→ 95
→ 90
→ 85
→ 반등
```

현재 구조에서는 100에서 한 번에 매수하기 때문에 95~85 구간의 더 낮은 가격을 활용하지 못합니다.

매도도 마찬가지입니다.

```text
100 매수
→ 110
→ 120
→ 130
→ SELL 신호
```

SELL 신호 시점에 전량 매도하면 이후 상승분을 놓칠 수 있습니다.

따라서 기존 전략 자체를 변경하지 않고, **전략의 BUY / SELL 신호와 실제 주문 실행 사이에 Position Manager를 추가하여 분할매수 / 분할매도 기능을 구현**해주세요.

---

# 2. 핵심 설계

기존:

```text
시장 데이터
↓
전략
↓
BUY / SELL / HOLD
↓
주문
```

변경:

```text
시장 데이터
↓
전략
↓
BUY / SELL / HOLD
↓
Position Manager
├─ 분할매수
├─ 분할매도
├─ 평균매수가 관리
├─ 추가매수 관리
├─ 익절 관리
├─ 손절 관리
└─ Trailing Stop
↓
Order Manager
↓
Upbit API
```

**전략의 신호 생성 로직과 실제 포지션 관리 로직을 분리해주세요.**

기존 전략의 BUY/SELL 조건 자체는 이번 작업에서 변경하지 마세요.

# 3. 분할매수

## 3.1 기본 개념

전략에서 BUY 신호가 발생하면 투자 예정 금액을 여러 단계로 나누어 진입할 수 있도록 해주세요.

기본 예:

```text
총 투자 예정금액 = 1,000,000원

1차 매수 = 30%
2차 매수 = 25%
3차 매수 = 20%
4차 매수 = 15%
5차 매수 = 10%
```

총합은 반드시 100%가 되어야 합니다.

## 3.2 고정 하락률 방식

```text
1차 = 신호 발생 가격
2차 = 최초 진입 가격 대비 -1%
3차 = 최초 진입 가격 대비 -2%
4차 = 최초 진입 가격 대비 -3%
5차 = 최초 진입 가격 대비 -5%
```

설정 예:

```text
entry_mode = percentage
entry_levels = [0, -1, -2, -3, -5]
entry_allocations = [30, 25, 20, 15, 10]
```

기본적으로 모든 하락률은 **최초 진입 기준 가격**을 기준으로 계산해주세요.

## 3.3 ATR 기반 방식

시장 변동성에 따라 추가매수 간격을 조정할 수 있도록 해주세요.

```text
entry_mode = atr
atr_period = 14
entry_atr_levels = [0, 1, 2, 3, 4]
```

ATR이 가격 단위로 계산되는 기존 프로젝트라면:

```text
추가매수가 = 최초 진입 가격 - ATR × level
```

방식을 사용해주세요.

---

# 4. 분할매수 안전장치

가격이 떨어진다고 무조건 추가매수하지 않도록 해주세요.

설정:

```text
allow_additional_entry = true
max_entry_orders = 5
max_position_ratio = 0.30
```

예를 들어 총자산이 10,000,000원이고 최대 포지션 비중이 30%라면 해당 포지션에 최대 3,000,000원까지만 투자해야 합니다.

**무한 물타기는 절대 허용하지 마세요.**

또한 최초 BUY 신호 이후 전략 조건이 완전히 무효화되면 추가매수를 중단할 수 있어야 합니다.

예:

```text
BUY 신호
↓
1차 매수
↓
가격 하락
↓
전략 상태 확인
├─ 유효 → 추가매수 가능
└─ 무효 → 추가매수 중단
```

# 5. 평균매수가

분할매수 후 다음 값을 정확히 관리해주세요.

```text
총 투자금
총 보유수량
평균매수가
```

평균매수가는 단순 가격 평균이 아니라 **수량 가중 평균**으로 계산해주세요.

---

# 6. 분할매도

SELL 신호 발생 시 전량을 한 번에 매도하지 않고 여러 단계로 매도할 수 있도록 해주세요.

예:

```text
보유수량 = 100%

1차 매도 = 20%
2차 매도 = 20%
3차 매도 = 25%
4차 매도 = 35%
```

총합은 100%여야 합니다.

## 6.1 수익률 기반

```text
평균매수가 = 100

1차 매도 = +3%
2차 매도 = +5%
3차 매도 = +8%
4차 매도 = +12%
```

설정:

```text
exit_mode = percentage
exit_levels = [3, 5, 8, 12]
exit_allocations = [20, 20, 25, 35]
```

모든 목표가는 현재 포지션의 평균매수가를 기준으로 계산해주세요.

## 6.2 ATR 기반

```text
exit_mode = atr
exit_atr_levels = [1, 2, 3, 5]
```

예:

```text
평균매수가 = 100
ATR = 2

1차 = 102
2차 = 104
3차 = 106
4차 = 110
```

# 7. SELL 신호 처리

SELL 신호가 발생했을 때 동작을 설정할 수 있게 해주세요.

```text
sell_signal_mode
```

지원:

```text
immediate
partial
ignore
```

### immediate

SELL 신호 → 남은 포지션 전량 매도

### partial

SELL 신호 → 설정된 비율만큼 부분 매도

### ignore

SELL 신호 → 설정된 분할매도 조건만 사용

단, **Stop Loss는 별도의 위험관리 조건으로 항상 우선 적용할 수 있어야 합니다.**

---

# 8. Trailing Stop

분할매도와 함께 Trailing Stop을 사용할 수 있도록 해주세요.

기본 설정:

```text
trailing_stop_enabled = true
trailing_stop_mode = atr
trailing_atr_multiplier = 2.0
```

최고가가 상승하면 Trailing Stop 가격도 상승해야 합니다.

한 번 상승한 Trailing Stop 가격은 가격이 하락한다고 다시 내려가면 안 됩니다.

예:

```text
가격: 100 → 110 → 120 → 130

최고가 = 130
Trailing Stop = 최고가 - ATR × multiplier
```

---

# 9. Stop Loss

분할매수 때문에 하락 포지션에 계속 추가매수하는 상황을 방지하기 위해 Stop Loss를 지원해주세요.

예:

```text
stop_loss_enabled = true
stop_loss_percent = -8
```

평균매수가가 100이면 -8%인 92에서 손절합니다.

Stop Loss 발생 시:

```text
남은 포지션 전량 매도
추가매수 중단
포지션 종료
```

---

# 10. 포지션 상태

다음과 같은 상태를 관리할 수 있도록 설계해주세요.

```text
ENTRY_ACTIVE
ENTRY_INVALIDATED
POSITION_ACTIVE
EXITING
CLOSED
```

최초 BUY 이후 전략 조건이 무효화되면 추가매수를 중단할 수 있어야 합니다.

---

# 11. Re-entry

선택적으로 재진입을 지원해주세요.

```text
reentry_enabled = false
```

기본값은 OFF입니다.

포지션이 종료된 후 다시 BUY 조건이 발생하면 새로운 포지션으로 진입할 수 있어야 합니다.

새로운 포지션에서는 다음 값을 초기화합니다.

```text
평균매수가
추가매수 횟수
분할매도 진행률
Trailing Stop
포지션 상태
```

---

# 12. 주문 상태 및 중복 주문 방지

실거래에서는 주문이 즉시 체결되지 않을 수 있으므로 다음 상태를 고려해주세요.

```text
PENDING
PARTIALLY_FILLED
FILLED
CANCELLED
FAILED
```

실제 포지션은 **주문 요청 수량이 아니라 실제 체결 수량**을 기준으로 업데이트해야 합니다.

또한 동일한 분할 단계가 반복적으로 주문되지 않도록 해주세요.

예:

```text
2차 매수 조건 충족
↓
2차 매수 주문 생성
↓
다음 polling
↓
조건 여전히 충족
```

이 경우 2차 매수 주문을 또 생성하면 안 됩니다.

단계별 상태를 관리해주세요.

```text
entry_level_1 = FILLED
entry_level_2 = PENDING
entry_level_3 = WAITING
```

# 15. 백테스트 연동

분할매수/분할매도는 반드시 백테스트에서도 동일하게 동작해야 합니다.

```text
Historical OHLCV
↓
Strategy
↓
BUY / SELL / HOLD
↓
Position Manager
↓
Virtual Order
↓
Portfolio
```

가능하면 실거래와 백테스트가 동일한 Position Manager 로직을 사용하도록 해주세요.

---

# 16. 백테스트 체결 가격

분할매수/분할매도에서는 목표가격에 실제로 도달했는지를 OHLC 데이터로 확인해야 합니다.

예:

```text
현재 캔들 종가 = 100
2차 매수 조건 = 98
```

해당 캔들의:

```text
Low <= 98
```

이면 98 부근에서 주문이 체결된 것으로 시뮬레이션할 수 있어야 합니다.

단, 한 캔들 안에서 고가와 저가가 여러 주문 가격을 통과한 경우 OHLC만으로 정확한 순서를 알 수 없습니다.

이 경우 임의로 유리한 체결 순서를 선택하지 말고 **보수적인 체결 규칙을 정의하여 적용**해주세요.

Look-ahead bias가 발생하지 않도록 주의해주세요.

# 23. 중요 구현 원칙

1. 미래 데이터를 사용하지 마세요.
2. 백테스트와 실거래의 Position Manager 로직을 동일하게 유지해주세요.
3. 분할매수는 무한 물타기가 되지 않도록 제한해주세요.
4. 실제 체결 수량을 기준으로 포지션을 업데이트해주세요.
5. 동일한 분할 단계의 중복 주문을 방지해주세요.
6. 평균매수가는 수량 가중 평균으로 계산해주세요.
7. 수수료와 슬리피지를 중복 적용하지 마세요.
8. 한 캔들의 OHLC만으로 알 수 없는 체결 순서를 임의로 유리하게 처리하지 마세요.
9. 새로운 기능의 기본값은 OFF로 설정해주세요.
10. 기존 전략의 BUY/SELL 조건은 변경하지 마세요.
11. 분할매수가 수익률을 높인다는 전제로 구현하지 말고, 기존 일괄매매와 객관적으로 비교할 수 있도록 해주세요.

# 24. 최종 목표

최종 구조:

```text
                    ┌───────────────┐
                    │  Market Data  │
                    └───────┬───────┘
                            ↓
                    ┌───────────────┐
                    │ Strategy      │
                    │ BUY/SELL/HOLD │
                    └───────┬───────┘
                            ↓
                 ┌──────────────────────┐
                 │   Position Manager   │
                 │                      │
                 │ Entry                │
                 │ ├─ 분할매수           │
                 │ ├─ 고정 하락률         │
                 │ └─ ATR                │
                 │                      │
                 │ Position             │
                 │ ├─ 평균매수가          │
                 │ ├─ 포지션 크기         │
                 │ └─ 최대 투자금         │
                 │                      │
                 │ Exit                 │
                 │ ├─ 분할매도            │
                 │ ├─ 익절               │
                 │ ├─ Stop Loss          │
                 │ └─ Trailing Stop      │
                 │                      │
                 │ Re-entry             │
                 └──────────┬───────────┘
                            ↓
                    ┌───────────────┐
                    │ Order Manager │
                    └───────┬───────┘
                            ↓
                       Upbit API
```

최종 목적은 **특정 전략 신호가 발생한 순간에 한 번에 전량 매수/매도하는 구조를 개선하는 것**입니다.

분할매수를 통해 전략 신호 이후 더 낮은 가격에서 추가 진입할 수 있게 하고, 분할매도를 통해 상승 과정에서 단계적으로 수익을 확보하면서 남은 물량은 추가 상승 가능성을 유지할 수 있도록 만들어주세요.

단, 이것이 반드시 수익률을 높인다는 전제로 구현하지 말고, **백테스트에서 기존 일괄매매 방식과 분할매매 방식을 객관적으로 비교할 수 있도록 구현하는 것**을 목표로 합니다.
