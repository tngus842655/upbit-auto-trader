현재 개발 중인 Upbit 자동매매 프로그램에 **웹 기반 대시보드 및 관리자 제어 화면**을 추가해줘.

핵심 구조는 **자동매매 엔진과 웹 UI를 분리**하는 것이다. 자동매매 엔진*은 웹사이트가* 종료되거나 접속하지 않아도 독립적으로 계속 실행되어야 하며, 웹 대시보드는 엔진의 상태를 조회하고 필요한 설정을 변경하거나 제어하는 역할을 한다.

### 대시보드

한눈에 현재 자동매매 상태를 확인할 수 있도록 구성한다.

- 봇 상태: RUNNING / PAUSED / STOPPED
- Trading Mode: BACKTEST / PAPER / LIVE
- 총 자산
- 현재 현금 잔고
- 보유 코인 및 포지션
- 오늘 수익률
- 누적 수익률
- 최대 낙폭(MDD)
- 최근 거래 내역
- 현재 전략 신호
- 최근 시스템/API 오류
- 실시간 자산 변화 및 수익률 차트

### 관리자 설정 화면

웹 UI에서 다음 설정값을 확인하고 변경할 수 있도록 한다.

- 거래 대상 코인
- 사용하는 전략
- 캔들 시간봉
- 전략 파라미터
- 거래당 최대 투자금
- 최대 포지션 비율
- 손절/익절 설정
- 일일 최대 손실
- 기타 Risk Management 설정

설정 변경사항은 즉시 무조건 적용하지 말고, 안전하게 저장한 뒤 **다음 거래부터 적용**할 수 있는 구조를 우선 고려한다.

### 봇 제어 화면

다음 기능을 제공한다.

- Start
- Pause
- Stop
- Paper Trading / Live Trading 상태 확인
- 현재 API 연결 상태
- WebSocket 연결 상태
- 마지막 데이터 수신 시간
- 마지막 거래 시간

특히 LIVE 거래는 실수로 활성화되지 않도록 별도의 확인 절차와 안전장치를 둔다.

### UI 방향

단순한 관리자 페이지가 아니라 실제 자동매매 프로그램을 운영하면서 계속 확인할 수 있는 **깔끔하고 직관적인 트레이딩 대시보드** 느낌으로 디자인한다.

데스크톱을 우선하되 반응형으로 구성한다.

### 기술 구조

기존 Python 자동매매 엔진과 FastAPI를 Backend로 사용하고, Frontend는 적절한 현대적인 웹 프레임워크를 사용한다.

Frontend ↔ FastAPI ↔ Trading Engine ↔ Upbit API

구조로 만들고, 실시간 상태나 거래 데이터는 가능하면 WebSocket을 활용한다.

대시보드가 자동매매 로직을 직접 수행해서는 안 되며, **Trading Engine이 실제 매매의 유일한 주체**가 되도록 설계한다.

기존 프로젝트 구조를 먼저 확인한 후 현재 코드와 자연스럽게 통합하고, 필요하다면 기존 구조를 개선한다.
